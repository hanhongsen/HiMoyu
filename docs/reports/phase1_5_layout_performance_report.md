# HiMoyu 阶段 1.5 · 办公室空间布局与 3D 性能验收报告

- 日期：2026-11-08
- 场景：`src/game/scenes/prototype_3d/office_full_25.tscn`
- 引擎：Godot 4.7.2-stable (official)，`gl_compatibility` 渲染器
- 结论：三区布局、正面偏俯视正交相机、25 工位编号与 5 分钟性能长跑均已完成；1920×1080 下 25 人同屏平均 69.5 FPS、最低 63.0 FPS。

> 本报告中的截图与数据全部来自本机真实 Godot 运行输出，未使用 AI 生成图片或后期合成。

## 一、本次布局调整

### 1. 左侧：老板玻璃办公室（新增）

- 位置：房间左后方，玻璃盒体占 `x = -11.05 … -8.05`、`z = -7.90 … -4.60`，净高约 3.0m。
- 结构：四面透明玻璃墙（玻璃高 2.55m，含深色框），正面开 0.90m 门洞并配置一扇半开的玻璃门，入口一目了然；背部玻璃与房间后墙贴合。
- 家具与陈设：2.0×1.0m 老板桌（金属腿 + 木桌面）、深色高背老板椅、显示器、笔记本电脑、文件、咖啡杯、台灯、BOSS 铭牌、专属地毯、后墙书柜（1.70×2.10m，含分层书籍）、角落绿植。
- 视觉：玻璃门上贴 `BOSS OFFICE` 标识（Label3D，贴在玻璃上），在全景中可清楚辨认。

### 2. 左侧：主管工位（保留并正式定位）

- 位置：老板办公室外侧、员工区左前方（根节点约 `x = -6.62, z = -3.30`），与老板办公室保持独立，不混在同一空间。
- 家具：2.0×1.0m 独立办公桌、显示器、灰色高背椅、双层文件架、咖啡杯、笔筒、`SUPERVISOR` 铭牌。
- 区域标识：新增主管专属地毯（浅青灰，2.70×1.80m），使观众在全景中一眼区分主管工位与普通员工工位。
- 本阶段未增加老板/主管角色与管理权限。

### 3. 中间：25 个固定工位

- 保持 5 列 × 5 行，列距 2.08m、排距 1.95m，工位编号 01–25。
- 位置：`x = -4.16 … 4.16`，`z = -4.90 … 2.90`，仍然是画面主体，未因扩大会议室而压缩。
- 每工位含木质桌椅、显示器、键盘、文件、桌面摆件与趴桌睡觉的员工。
- 员工外观差异（肤色、发型、服装配色、配饰）与睡姿动画全部保留。

### 4. 右侧：扩大后的会议室

- 范围：`x = 5.95 … 11.00`、`z = -8.08 … 0.60`，横向从原来的小隔间扩展到接近房间东墙，充分利用了右侧空余空间。
- 结构：西侧与正面使用玻璃隔断，正面开 0.90m 门洞并配置半开玻璃门；玻璃上贴 `MEETING ROOM` 标识。
- 家具：3.40×1.15m 会议长桌、8 把会议椅（两侧各 3 把、两端各 1 把）。
- 展示设施：后墙 2.05×1.28m 白板（带示意图线条）与 1.70×1.32m 投影幕；东墙书柜与三抽屉文件柜；两处绿植；4.70×2.75m 地毯。
- 为后续镜头放大预留了完整的桌面与椅子展示空间。

### 5. 三区平衡

- 老板办公室、主管工位、25 工位区与会议室共用同一地板、后墙与窗户，未出现“三张图片拼接”的割裂感。
- 区域之间留有通道：老板室与员工区之间、员工区与会议室之间均有 1m 以上的走道。
- 家具按坐标单独校核，无交叉摆放；玻璃隔断高度低于吊顶，不遮挡后墙窗户与主要视觉内容。

## 二、摄像机视角调整

### 1. 新视角

- 由原来的斜向等距视角改为**正面偏俯视（Frontal Elevated View）**。
- 使用正交摄像机（`projection = 1`），水平旋转为 0（无 yaw），与办公室布局轴线对齐。
- 俯角约 35°（相机位于场景正前方并抬高），可以看到桌面、员工脸部与睡觉动作，但不会变成 90° 纯俯视。

### 2. 参数

| 参数 | 值 |
|---|---|
| 投影方式 | Orthographic |
| 相机偏移 | `(0, 14.95, 21.35)` |
| 目标点 | `(0, 1.80, -1.0)` |
| 正交尺寸 | 13.4 |
| 远裁剪 | 100 |
| 水平旋转 | 0° |

- 1920×1080 下水平可视宽度约 23.8m，完整覆盖 22.4m 房间；左侧老板办公室、中间 25 工位、右侧会议室均未被裁切。
- 25 名员工全部在画面内，人物之间无严重遮挡。

### 3. 新旧视角对比

| 项目 | 旧版（阶段 1） | 新版（阶段 1.5） |
|---|---|---|
| 视角方向 | 斜向 45° 等距（有明显对角线） | 正面偏俯视，无水平旋转 |
| 桌面朝向 | 斜对镜头 | 主要正面朝向观众 |
| 画面用途 | 游戏化俯视 | 抖音横屏直播画面 |
| 工位横向/纵向 | 倾斜排列 | 横竖整齐对齐 |

## 三、25 个工位编号检查

### 1. 编号规则

- `seat_index = row × 5 + col + 1`，`row` 从房间后侧（画面顶部）向前递增，`col` 从左侧向右递增。
- 与 2D 版本的 `col = i % 5`、`row = i / 5` 以及引擎 `SeatState.index`（1–25）保持一致，视觉位置的调整没有破坏原有数据对应关系。
- 员工与工位由同一 `seat_index` 绑定：`Workstation3D.seat_index` 与 `Employee3D.seat_index` 相同，角色坐在自己的工位上。

### 2. 检查结果

| 检查项 | 结果 |
|---|---|
| 是否存在遗漏编号 | 无，01–25 全部存在 |
| 是否存在重复编号 | 无，25 个编号唯一 |
| 编号与员工绑定 | 一一对应，共 25 对 |
| 角色是否坐在正确工位 | 是，工位根节点直接生成对应员工 |
| 新视角下编号显示 | 01–25 全部可见可读 |

### 3. 号牌可读性修正

- 原号牌贴在桌子正面（y≈0.585），正面偏俯视下会被**前排椅背**遮挡，实测只有最前排 21–25 可读。
- 本次改为**桌面立牌**：0.300×0.185m 白色立牌立在桌面（中心 y≈0.855），底部带金属小底座，`Label3D` 字号 76、`pixel_size` 0.0023。
- 修改后 5 排 25 个号牌全部露出，1920×1080 原图下可清楚读出两位数编号，且不遮挡员工脸部、手臂与显示器。

## 五、优化内容

### 1. 静态网格合并（主要收益）

- 在 `mesh_kit.gd` 新增 `bake_static(root, dynamic_group)`：
  - 遍历场景中的静态 `MeshInstance3D`，按“材质 + 投影设置”分桶，用 `SurfaceTool.append_from()` 合并为少量 `ArrayMesh`。
  - 本次合并后静态表面 **85 个**，原来数千个静态 `MeshInstance3D` 被替换。
  - 动态组 `dynamic_3d` 会被跳过，员工的动画节点不受影响。
- 场景级调用：25 套工位家具 + 房间全部静态装饰（桌椅、显示器、白板、书柜、玻璃框、绿植等）统一合并。

### 2. 员工动画分组保留

员工内部按“可动组”分别合并，动画完全保留：

| 部件 | 处理方式 | 保留动画 |
|---|---|---|
| 腿部 | 整体静态合并 | 无（腿部本来不动） |
| 胸腔 | 合并后仍挂在 `Chest` 下 | 呼吸缩放 |
| 肩/脖/领口 | 放进独立 `TorsoStatic` 容器后合并 | 随身体前倾 |
| 头部/五官/发型/配饰 | 合并到 `HeadPivot` 下 | 头部轻晃 |
| 双臂/手/袖口 | 合并到 `ArmsOnDesk` 下 | 手臂轻浮 |
| Zzz | 保持动态生成 | 向上飘散 |

- 未关闭呼吸、头部轻晃、身体前后微晃、手臂浮动与 Zzz 动画。
- 未删除阴影、灯光或透明玻璃等视觉效果。

### 3. 其他

- 保持 1 个方向光 + 1 个补光、阴影距离 30m 不变。
- 玻璃材质保持透明（alpha 0.20），未改为不透明。
- 没有为了性能减少家具或员工数量。

## 六、优化前后性能数据

> 优化前数据来自阶段 1 的旧布局场景（同为 25 名员工、1920×1080、MSAA 4x、VSync 开，连续采样 120s）。新旧场景家具数量不同（新版新增老板办公室并扩大会议室），对比用于说明“同一机器、同一分辨率、同一员工规模”下的优化效果。

| 指标 | 优化前（旧布局） | 优化后（阶段 1.5） |
|---|---|---|
| 连续采样时长 | 120 s | 300 s |
| 采样帧数 | 4,623 | 20,857 |
| 平均 FPS | 38.5 | **69.5** |
| 最低 FPS（1 秒窗口） | 36.2 | **63.0** |
| 帧时间平均 | 25.96 ms | **14.38 ms** |
| 帧时间 P95 | 27.78 ms | **15.28 ms** |
| 帧时间最大 | 60.35 ms | 36.50 ms |
| Draw calls 平均 | 6,100 | **1,199** |
| 三角面平均 | 2,644,921 | 2,844,881 |
| MeshInstance3D 数量 | 3,011 | **553** |
| Label3D 数量 | 25 | 29 |

### 数据解读

- 旧版 `Draw calls ≈ 2 × MeshInstance3D`（3011 × 2 ≈ 6022，加上少量其他绘制 ≈ 6100），说明 6096/6100 并不是异常读数，而是**阴影 pass + 主 pass** 的合计，主要来源是数量过多的独立 MeshInstance。
- 静态合并后 MeshInstance 降到 553，Draw calls 降到 1199（约 -80%），平均 FPS 从 38.5 提升到 69.5（约 +81%）。
- 三角面从 2.645M 微增到 2.845M（+7.6%），原因是新增老板办公室、书柜、扩大会议室与更多会议椅；属于预期增加，不是性能回退。
- 本机屏幕刷新率高于 60Hz，垂直同步开启时仍测得 69.5 FPS；在 60Hz 显示设备上运行时帧率会被垂直同步锁定在 60 FPS。
- 最差单帧 36.50ms 为个别抖动（窗口/系统调度或资源瞬间），P95 为 15.28ms，整体稳定。

## 九、尚未解决的问题

1. 本机为 Intel Iris Xe 核显，性能数据仅代表该硬件；高端独显上会更高，低端设备可能低于 60 FPS。
2. 剩余约 1199 draw calls 主要来自 25 个动态员工分组、Zzz 标签、桌面立牌与透明玻璃；若未来加入更多独立动态对象，需要做按距离/区域的可见性裁剪。
3. 三角面约 2.84M，方向光阴影仍会为大部分静态物体生成阴影 pass；若后续需要更高帧率，可考虑降低阴影距离或对小物件关闭投影（本次为保视觉未改）。
4. 透明玻璃与 Label3D 均为透明材质，镜头大幅推近时可能出现轻微排序问题，需要在后续镜头放大/切换阶段专项验证。
5. 会议室东墙书柜贴墙且正面朝西，在全景中主要呈现侧面轮廓，辨识度一般；后续可考虑旋转或前移。
6. 本次只完成静态全景验收，未实现镜头自动放大、切换与互动触发。
